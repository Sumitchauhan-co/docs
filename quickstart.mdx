This quickstart shows the standard OIDC sign-in flow for public clients and confidential web apps.

## Prerequisites

- An OIDC client registered in your dashboard.
- A redirect URI that your app controls.
- HTTPS in production.
- A library that supports OpenID Connect discovery and PKCE.

## 1. Discover provider metadata

Fetch the discovery document to find the authorization, token, userinfo, JWKS, and logout endpoints.

```bash
curl https://protoauth.vercel.app/.well-known/openid-configuration
```

Use the `issuer` value from discovery when you validate tokens. The value must match exactly.

## 2. Create a PKCE verifier and challenge

Generate a high-entropy `code_verifier`. Send its SHA-256 challenge in the authorization request.

```js
const codeVerifier = crypto.randomUUID() + crypto.randomUUID();
const digest = await crypto.subtle.digest(
  "SHA-256",
  new TextEncoder().encode(codeVerifier)
);
const codeChallenge = btoa(String.fromCharCode(...new Uint8Array(digest)))
  .replace(/\+/g, "-")
  .replace(/\//g, "_")
  .replace(/=+$/, "");
```

Store `codeVerifier` server-side or in protected client storage until the callback completes.

## 3. Redirect the user to authorize

```text
GET https://protoauth.vercel.app/o/authenticate?
  response_type=code&
  client_id=client_123&
  redirect_uri=https%3A%2F%2Fapp.example.com%2Fcallback&
  scope=openid%20profile%20email&
  state=af0ifjsldkj&
  nonce=n-0S6_WzA2Mj&
  code_challenge=CODE_CHALLENGE&
  code_challenge_method=S256
```

Use `state` to protect the redirect. Use `nonce` to bind the ID token to the sign-in request.

## 4. Exchange the code for tokens

After authentication, the provider redirects back to your app with `code` and `state`.

```bash
curl --request POST https://protoauth.vercel.app/o/token \
  --header "Content-Type: application/x-www-form-urlencoded" \
  --data "grant_type=authorization_code" \
  --data "client_id=client_123" \
  --data "redirect_uri=https://app.example.com/callback" \
  --data "code=AUTHORIZATION_CODE" \
  --data "code_verifier=CODE_VERIFIER"
```

Confidential clients should authenticate with a client secret or another configured client authentication method.

## 5. Validate the ID token

Validate the ID token before you create a local session.

- Confirm the token signature with the provider JWKS.
- Confirm `iss` equals the issuer from discovery.
- Confirm `aud` includes your `client_id`.
- Confirm `exp` and `iat` are valid.
- Confirm `nonce` matches the original request.

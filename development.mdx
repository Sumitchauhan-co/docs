Use local development settings that match production behavior without weakening your production client.

## Redirect URIs

Register explicit local callback URLs for each app you run.

```text
https://app.example.com
http://localhost:5173
```

Do not use wildcard redirect URIs unless your deployment explicitly supports a safe, narrow pattern.

## Test users

Create dedicated test users for development and CI. Give each user only the permissions needed for the scenario under test.

## Environment variables

Store OIDC settings outside your source code.

```bash
OIDC_ISSUER=https://auth.example.com
OIDC_CLIENT_ID=client_123
OIDC_CLIENT_SECRET=replace-me
OIDC_REDIRECT_URI=http://localhost:5173
```

Never commit client secrets, refresh tokens, authorization codes, or private keys.

## Debug checklist

- The `redirect_uri` in the authorization request exactly matches a registered URI.
- The `issuer` in your app exactly matches the discovery document.
- Your app sends `code_challenge_method=S256`.
- The callback handler checks `state` before it exchanges the code.
- Your system clock is synchronized before validating `exp`, `iat`, and `nbf`.

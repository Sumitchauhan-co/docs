---
title: "Refresh tokens"
description: "Renew access without sending users through sign-in again"
icon: "rotate"
---

Use refresh tokens when your app needs long-lived access and your provider policy allows it.

## Request offline access

Include `offline_access` in the authorization request.

```text
scope=openid profile email offline_access
```

Some providers require explicit consent before issuing refresh tokens.

## Exchange a refresh token

```bash
curl --request POST https://auth.example.com/oauth2/token \
  --header "Content-Type: application/x-www-form-urlencoded" \
  --data "grant_type=refresh_token" \
  --data "client_id=client_123" \
  --data "refresh_token=REFRESH_TOKEN"
```

Confidential clients should authenticate to the token endpoint.

## Rotate stored values

If the response includes a new refresh token, replace the stored token immediately.

<Warning>
  If refresh token reuse is detected, revoke the session and ask the user to sign in again.
</Warning>
